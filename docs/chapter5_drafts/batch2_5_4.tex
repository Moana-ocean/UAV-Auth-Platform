\section{Normal Authentication Results}
\label{sec:ch5-normal-auth}

Normal authentication was evaluated with the \texttt{valid\_active} scenario across identity counts $n \in \{10,50,100,250,500\}$ and concurrency levels $c \in \{1,5,10,25,50\}$ for each mechanism (50 runs; steps 3--52 of the matrix). Table~\ref{tab:ch5-acceptance} reports acceptance outcomes after excluding warm-up attempts.

For the X.509 baseline, every scalability run achieved full acceptance: $n_{\mathrm{accepted}} = 30$ of $n_{\mathrm{measured}} = 30$ with zero false rejections and zero timeouts across all 25 configurations (e.g.\ run \texttt{n500-identities\_c50-conc\_mech-x509-1backend\_valid-active\_r30\_audit-off\_20260820T022732Z}).

For the blockchain mechanism, the same 25 scalability runs recorded \textbf{zero acceptances}: $n_{\mathrm{accepted}} = 0$, $n_{\mathrm{false\_rejections}} = 30$ per run, with observed reason codes inconsistent with the expected \texttt{ACCEPTED} outcome (see \texttt{07\_data\_quality\_report.md}). This systematic anomaly affects interpretation of blockchain normal-authentication performance in Sections~\ref{sec:ch5-latency} and~\ref{sec:ch5-comparison} and is treated as an implementation defect in the evaluated matrix rather than as evidence that legitimate blockchain authentication is inherently impossible.
