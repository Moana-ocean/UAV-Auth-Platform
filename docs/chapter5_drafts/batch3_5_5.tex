\subsection{UAV Spoofing Test Results}
\label{sec:ch5-spoofing}

Spoofing was tested with \texttt{unknown\_uav} (unregistered identity) and \texttt{impersonation\_wrong\_key} (registered identity, incorrect private key). Both mechanisms rejected all 30 attempts per scenario with zero false acceptances. X.509 mean decision latencies were 0.25~ms and 2.14~ms respectively; blockchain latencies were 20.48~ms and 16.28~ms, reflecting registry lookup via \texttt{eth\_call} before rejection.

\subsection{Replay Attack Test Results}
\label{sec:ch5-replay}

Replay attempts reused a previously accepted signed payload. All 30 repetitions were rejected with \texttt{expectation\_met=true} for both mechanisms (X.509 mean 0.03~ms; blockchain mean 0.04~ms). No false acceptances were observed.

\subsection{Message Tampering Test Results}
\label{sec:ch5-tampering}

Tampering scenarios altered the nonce (\texttt{modified\_nonce}), UAV identifier (\texttt{modified\_uav\_id}), or requested operation (\texttt{modified\_operation}). Each scenario produced 100\% expected rejections with zero false acceptances for both mechanisms. Mean latencies remained below 3~ms for X.509 and between 18.4~ms and 19.9~ms for blockchain on these tests.

\subsection{Unauthorised Access Test Results}
\label{sec:ch5-unauthorised}

Unauthorised access was tested with \texttt{unauthorised\_operation} (role-limited identity requesting a disallowed operation) and \texttt{malformed} requests. Both mechanisms rejected all attempts with the expected reason codes (100\% expectation met). The blockchain-only \texttt{rpc\_unavailable} scenario confirmed graceful failure when the registry RPC endpoint was unreachable (mean latency approximately 69\,244~ms, consistent with configured authentication timeout behaviour).

\subsection{Revoked Identity Test Results}
\label{sec:ch5-revoked}

Revocation-related tests included \texttt{revoked\_uav}, \texttt{expired\_challenge}, and X.509-specific \texttt{expired\_certificate} and \texttt{untrusted\_issuer}. Both mechanisms met expectations in all cases (100\%) with zero false acceptances.

\textbf{RQ1 synthesis.} Under the security battery, both mechanisms prevented false acceptances across spoofing, replay, tampering, and revocation scenarios. X.509 satisfied all expected outcomes, including legitimate \texttt{valid\_active} acceptance (30/30). The blockchain path likewise satisfied all expected outcomes in this battery, including legitimate authentication (30/30) and correct rejection reason codes for unauthorised-operation tests.
